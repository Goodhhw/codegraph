  how to read this
    buckets    compare write+output. Cache reads are 20x cheaper than writes and
               dominate the token COUNT, not the bill; output is reconciled from
               total_cost_usd because the raw output_tokens field under-reports.
               Two runs sharing a prompt prefix inside one 1h cache window make
               the second one cheaper (write→read) — separate the arms' windows.
    occupancy  compare each arm's RETRIEVAL residual (codegraph in a with-arm,
               file-access in a without-arm). Shares are Claude Code on a 200k
               window and do NOT transfer to another host; the ratio does.
    sufficiency  pooled across runs because it is per-CALL. "explore again" is
               ambiguous by construction; "Read a file we returned" is an
               allocation miss, the two recall rows are recall misses.
    allocation  RELATIVE, not absolute — attribution is by citation, and an agent
               can use a file without naming it. Compare builds on the SAME
               question; never quote it as "codegraph wastes N% of what it returns."
    all three  small-n. Runs make 1–5 explore calls, so read the range, not the
               median of one run. RUNS>=2, and the 7-repo campaign for a verdict.
